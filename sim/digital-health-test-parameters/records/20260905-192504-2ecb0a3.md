## 1. Cutoff table over an H grid

`C_RCT = 1 + ceil(-log2(alpha)/H)`; `C_APT` = smallest `C` with
`Pr(X >= C) <= alpha` for `X ~ Binomial(W, 2^-H)`, evaluated with 80-digit
decimal arithmetic (a float sum of 1024 terms cannot resolve a 2^-40 tail).

| `H` | `C_RCT` | `C_APT` | note |
|---|---|---|---|
| 0.0390625 | 1025 | none | **degenerate** -- no valid cutoff exists |
| 0.04 | 1001 | 1024 | degenerate in practice (cutoff within 2 of the window) |
| 0.05 | 801 | 1022 | degenerate in practice (cutoff within 2 of the window) |

**Adopted**: `C_RCT` = 81, `C_APT` = 824 at `H` = 0.5.

These are the same two numbers gf180-trng's DR-0002 records, and that
is a **result, not a port**: the formulas are identical, `alpha` and `W`
are identical, and both repositories currently target `H = 0.5`. The
table above is the load-bearing artifact -- the moment sky130's measured
`H` differs, the cutoffs move with it, and the agreement disappears.
Recomputing them here from first principles also independently
reproduces gf180-trng's own published values, which is the cheapest
available check that this implementation of the formulas is right.

## 2. APT degeneracy floor

`Pr(X >= W) = p^W = 2^(-H*W)`, so a cutoff `C <= W` exists only while
`2^(-H*W) <= alpha`, i.e.

    H > alpha_log2 / W = 40 / 1024 = 0.0390625

- direct evaluation at the floor: `Pr(X >= W)` = 9.094947e-13 vs `alpha` = 9.094947e-13 (equal to the last bit -- the floor is an open bound)
- `H` = 0.0380625 (just below): `C_APT` = none
- `H` = 0.0400625 (just above): `C_APT` = 1024 of 1024 -- valid, and useless

gf180-trng's DR-0002 states this floor as "H ~ 0.03, marginal below
H ~ 0.05". The exact value at these parameters is **0.0390625**, and
the practical floor is higher still: at `H` = 0.05 the cutoff is
1022 of 1024, i.e. the test only fires when
essentially every sample in a window matches. Sky130's array is sized
to `H` = 0.5 (DR-0002/DR-0003), an order of magnitude clear of
the floor, so this is a stated risk boundary rather than an active
constraint -- but it is exactly the boundary issue #21's measurement
could move the design into, and it is checked here rather than assumed.

## 3. Why `alpha = 2^-40` survives re-derivation at 50 kbps

`alpha` is a false-alarm rate, and a false-alarm *rate* only becomes a
false-alarm *interval* once a sample rate is fixed. sky130-trng's rate
is 20x lower than the row gf180-trng's choice was argued against, so the
inherited number has to be re-justified rather than assumed:

| Quantity | sky130-trng (50 kbps) | gf180-trng (1 Mbps row) |
|---|---|---|
| RCT false-alarm interval (one decision per sample) | 254.5 days | 12.7 days |
| APT false-alarm interval (one decision per 1024-sample window) | 713.6 years | -- |

At this rate `alpha = 2^-40` is **more** conservative than gf180-trng's
own justification needed it to be. It is kept anyway (DR-0004 §2.2):
relaxing it would tighten the cutoffs slightly while buying no
meaningful detection latency --
`C_RCT` at `alpha = 2^-30` is 61 versus 81 at 2^-40, i.e.
0.40 ms of detection latency at 50 kbps -- and it keeps this
block's parameters directly comparable with the sibling repository's.
