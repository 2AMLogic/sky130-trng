# Friction ledger: filed `2AMLogic/klayout-tools` issues

This is the in-repo index of the tool gaps this port hit, per the friction
protocol in [`CLAUDE.md`](../CLAUDE.md). One row per distinct
`2AMLogic/klayout-tools` issue (or PR) referenced anywhere in the tree. It is
an index of upstream issues, not a design log and not the T1 tier checklist
(that is tracked in #3).

- **State is as of 2026-10-11** and is not re-synced automatically. The CI
  checker (`tools/check_friction_ledger.py`) is offline: it only verifies
  that every `klayout-tools#N` / `klayout-tools/issues/N` reference in the
  tree has a row here, not that the state column is current. Refresh the
  state column with
  `gh issue list -R 2AMLogic/klayout-tools --state all --limit 400`.
- "Description" is the upstream title (generic tool wording). Rows marked
  "PR" are merged upstream pull requests rather than issues.
- "Where it bit" lists up to three repo artifacts (per-run corner logs and
  records are collapsed to their `sim/<dir>/`). "Fixed in" is stated only
  where this repo records the version; otherwise the state column says
  closed/merged without a version.
- References inside the vendored `.loom/` tooling are not klayout-tools
  issues and are ignored by the checker.

To add a row: append it (number in the first column as `[#N](...)`) when you
file or cite a new klayout-tools issue; keep it sorted by number.
